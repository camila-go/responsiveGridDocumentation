How a component responds

The CTA below is one block of markup with no viewport media queries. It sizes off its own width using container queries, so it is correct at .l-max, at .l-min, and inside a three-column grid — the grid decides how much room it gets, the component decides what to do with it.

Each frame is a real page at that width, scaled down to fit. The tier label under each one reports which container query is active.

Padding is 32px on desktop, 16px on mobile. That makes the padding DT 1027 study in the Grid page the authoritative one — it draws 1024 → 960 / 780, which is exactly what the formula produces. The padding DT 1024 frame next to it (80px) is the superseded option.

1440 is the default. Padding sits outside that rail, not inside it, so content reaches its 1440 cap once the viewport is 1504 (1440 + 2×32) or wider — the 1440 row above shows the cap not yet reached. 1504 is a consequence of --grid-pad-desktop, not a design number; don’t hardcode it, and don’t quote it as the default width. The 1600 written on the Grid page was the same arithmetic with the old 80px padding, and is stale.

Not in the design files: column count and gutter. The gutter defaults to 24px (3× the system’s 8px base unit) via --grid-gutter.
